> **현재 단계: 플레이 가능한 HTML 콘셉트 프로토타입 / 본 문서는 개선 로드맵**

## 1. 게임의 핵심 방향

플레이어는 던전의 주인이 되어 몬스터를 고용·배치하고 특성을 부여한다. 마을 술집 등에서 모험가의 소문을 수집하고, 제한된 하루 24시간을 정보 수집·방어 준비·경제 활동에 배분한다. 침입자가 왔을 때 준비한 구조와 상성이 작동하는 것을 직접 확인하며 던전을 유지·확장한다.

**핵심 재미:** 정보를 통해 적의 행동을 예측 → 제한된 자원을 투자해 던전 방어를 구성 → 침입 과정과 인과관계를 관찰 → 결과에 따라 다음 전략을 수정.

**제외 범위(확정):** 몬스터 자율 생태계, 공진화, 자동 진화. 특성은 플레이어가 직접 부여하는 선택 시스템이며, 단순 공격력 수치 강화 위주로 설계하지 않는다.

**현재 한계:** 전투는 총 방어력과 요구량을 비교해 처리한다. 방 위치가 결과에 주는 영향이 제한적이며, 방어 과정이 실제 공간 속 전투로 보이지 않는다. 사용자의 “버튼만 누른다”는 지적을 해결하려면 수치 조정보다 게임 세계의 시각화와 공간적 의사결정을 우선해야 한다.

## 4. 단계별 개발 계획

### P0 — 손맛이 느껴지는 최소한의 던전

- [ ] **2D 던전 맵:** 방·통로·입구·핵심실을 한눈에 보여주고, 선택한 방에 배치 가능한 몬스터를 표시한다.
- [ ] **직접 조작:** 드래그 배치 또는 클릭-선택-배치(모바일 접근성 대안). 이동 가능 위치·행동 비용을 미리 보여준다.
- [ ] **시각적인 침입:** 모험가가 통로로 입장해 방을 이동하고, 몬스터와 충돌하면 전투가 발생한다. 일시정지·배속·건너뛰기를 제공한다.
- [ ] **실질적인 위치 전략:** 방의 순서, 몬스터의 역할, 함정 위치가 피해·지연·생존에 영향을 준다. 단순 수치 총합만으로 승패를 결정하지 않는다.
- [ ] **결과 설명:** '누가/어디서/어떤 효과로/왜' 방어에 성공했거나 실패했는지 전투 리플레이와 사건 일지에 표시한다.
- [ ] **초보자 첫 전투:** 추천 배치로 곧바로 시작 → 소문 한 개 확인 → 몬스터 한 마리 이동 → 침입 결과 체험. 새로운 시스템을 한 번에 모두 노출하지 않는다.
- [ ] **밸런스 재검증:** 5일차를 포함한 다양한 특성 조합, 소문을 놓친 경우, 코인을 적게 번 경우에도 의미 있는 회복 수단이 있는지 검사한다.

**P0 완료 기준:** 초보자 5명 중 최소 4명이 추가 설명 없이 1분 이내 첫 행동을 하고, 한 판이 끝난 후 자신의 성공·실패 이유를 대략 설명할 수 있을 것. 이 수치는 개발 목표이며 현재 측정 결과가 아니다.

### P1 — 경영과 정보전 확장

- [ ] **술집 NPC와 소문:** NPC 대화·게시판 등으로 단서를 얻는다. 정보의 정확도와 상세도가 다르며, 더 정확한 정보에는 시간 또는 돈이 든다.
- [ ] **행동 일정표:** 하루 24시간을 시각적인 타임라인으로 표현해 배치, 의뢰, 탐색, 시설 정비의 기회비용을 보여준다.
- [ ] **경제 순환:** 격퇴 보상과 몬스터 사회의 화폐를 사용해 새 몬스터, 특성, 함정, 시설을 마련한다. 코인 수급과 소모의 의미를 유지한다.
- [ ] **몬스터 특성 다양화:** 매복, 추격 차단, 방어구 손상, 기습 대응, 사망 시 길 막기처럼 플레이 방식을 바꾸는 효과 위주로 구성한다.
- [ ] **함정·지형과 연계:** 좁은 통로, 우회로, 지형 효과를 통해 정보 수집 결과와 방어 설계가 연결되게 한다.
- [ ] **정예 모험가 이벤트:** 특정 날짜에 엘리트 또는 이름 있는 모험가가 방문한다. 사전 단서와 대응 기회를 충분히 제공한다.
- [ ] **성장 목표:** 던전 확장과 새로운 방어 선택을 해금한다. 단순히 적의 방어 요구량만 빠르게 증가시키지 않는다.

### P2 — 확장 및 완성도

- [ ] 모험가 직업·행동 패턴 추가(정보에 기반한 예측 가능성 유지)
- [ ] 여러 방어 전략이 성립하도록 난이도별 시나리오 및 반복 플레이 콘텐츠 제공
- [ ] 저장/불러오기, 접근성·모바일 조작 최적화, 사운드 및 가벼운 연출
- [ ] 이벤트와 UI에 대한 회귀 테스트와 밸런스 테스트 자동화

## 5. 밸런스 설계 원칙

1. **난도가 높아지는 이유를 보여준다.** 정예 모험가의 능력·장비·습관 등으로 위협을 설명한다.
2. **수치 인플레이션만으로 난도를 만들지 않는다.** 방어 요구량만 오르는 대신 새로운 행동 패턴에 대한 대응을 요구한다.
3. **플레이어에게 대응책을 준다.** 새로운 위협 전에 단서, 위치 변경, 특성·함정 선택 등 실질적인 선택지가 있어야 한다.
4. **패배 후 회복을 허용한다.** 한 번의 실수로 연속 패배가 확정되지 않도록 수입·수리·대체 전술을 설계한다.
5. **자동화 테스트를 도입한다.** 추천 조합뿐 아니라 무작위 조합과 자원 부족 시나리오도 여러 회차 시뮬레이션한다.
6. **다양한 정답을 유지한다.** 필수 특성이 하나로 고정되면 정보전과 배치 전략의 의미가 사라진다.

## 6. UX 및 플레이 테스트

- [ ] 10초 이내 게임 목표를 파악하는지 관찰
- [ ] 설명 없이 30~60초 내 첫 행동을 수행하는지 관찰
- [ ] 어떤 정보를 보고 몬스터를 배치했는지 설명할 수 있는지 관찰
- [ ] 방어 실패를 보고 바꿔야 할 전략을 떠올리는지 관찰
- [ ] 한 판 후 재도전 의사가 있는지 질문
- [ ] 같은 곳에서 막히는 사용자가 반복되면 UI와 흐름부터 수정

**원칙:** 조작은 간단하게, 정보는 명확하게, 전략은 깊게. '최선의 수'를 고민하는 시간은 늘리고, '어떤 버튼을 눌러야 하는지' 헤매는 시간은 줄인다.

## 7. 당장 다음 개발 작업 제안

**첫 번째 작업은 던전 맵 + 침입 애니메이션 + 방별 상호작용을 하나의 작은 수직 슬라이스로 만드는 것.** 처음부터 방과 몬스터를 수십 종 추가하지 않는다. 몬스터 4종, 방 4개, 모험가 3종과 정예 이벤트 정도를 유지한 채 실제로 '배치하고 지켜보는 재미'가 있는지 검증한다.
